# Снимок реальной схемы

Подтверждённый production-экспорт пока не предоставлен. Здесь не создаются предполагаемые миграции или синтетический снимок каталога.

Сохранить полный исходный schema-only SQL и неперсональный metadata report после получения: версия сервера, engines, индексы/FK, morph aliases/key, MAX(id), дубли и определения views/triggers. Сырые SQL/JSON файлы исключены из Git и образов.

Автоматический локальный импорт принимает отдельный table-DDL файл. Views/triggers требуют проверки и отдельного восстановления в изолированном клоне. До этого соответствие production-схеме не подтверждено и запись не включается. После проверки можно подготовить очищенный canonical snapshot для version control отдельным явным шагом.

Служебные миграции `orbita_*` находятся в соседней папке `migrations`; каталоговые DDL туда не переносятся.

## Восстановление после утраты базы (2026-10-14)

По CSV и найденному архиву миграций подготовлена отдельная реконструкция в `../recovery`.
Она не является подтверждённым production-снимком и не подключается к служебным миграциям.
Источники, допущения, manifest и инструкция запуска: [orbita-db README](../../README.md).
