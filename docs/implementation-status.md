# Состояние реализации

## Реализовано

- Витрина и отдельная админка на Svelte 5 / SvelteKit 3 / Tailwind 4.
- Laravel 13 / Lighthouse 6.71: авторизация сотрудников, scoped catalog API, CRUD/архивирование/восстановление, загрузка изображений.
- Заказы со снимком цен, дробными количествами, идемпотентностью, durable outbox и адаптером ЮKassa.
- Служебные миграции `orbita_*`, общий allocator ID, проверка реальной схемы и закрытый по умолчанию gate записи.
- Docker Compose local/production, worker/scheduler, внешняя production-БД, Nginx и скрипты проверки/выпуска.
- Перенос публичных страниц и контента, исправления адаптивности, доступная корзина/поиск и защищённый просмотр заказов.

## Визуальная проверка

Сохранены 36 финальных снимков: главная и контакты на 360/390/768/1024/1440 px, пустая/заполненная корзина, категория и распродажа на 390/1440 px. Проверены загрузка изображений, футер, работа поиска и отсутствие переполнения.

Независимый review подтвердил восстановление исходной палитры, основных блоков, контактов и реквизитов. Финальный verdict покрыл ссылки проезда и уведомления. Отрисовка внешней карты по снимкам не подтверждена; вне iframe доступны две ссылки маршрута. Полное пиксельное соответствие корзины/категории/распродажи не заявляется: для них проверены состояния и исходный код, а исходные сравнительные снимки сохранены только для главной и контактов.

Механический design detector выполнен в ограниченном режиме без HTML/CSS parser modules; он не является полной проверкой контраста или accessibility.

## Перед production

1. Получить полный schema-only экспорт и неперсональные метаданные существующей БД.
2. Сверить реальные таблицы, SQL-типы, aliases, pivots, views и triggers; восстановить полноценный изолированный клон и завершить соответствующие mappings.
3. Перевести всех writers на общий allocator, проверить snapshot/fingerprint и подтвердить gate.
4. Настроить production APP_KEY, DB/SMTP/S3/ЮKassa и действующий механизм чеков; проверить провайдеры в разрешённой тестовой среде.
5. Выполнить предусмотренный staging/backup/cutover процесс. До этих шагов запись в каталог и реальные платежи остаются выключенными.

Production-БД, реальные платежи и внешняя отправка писем для проверок не использовались.
